# Bilingual frontend integration

The same-origin frontend uses native browser modules and existing CSS, without runtime dependencies or external requests. Authentication, CSRF headers, redirect rejection and private downloads continue through `GroceryClient`. Existing control IDs remain available; browser workflows now navigate through the hash panels before interacting with Pantry, Offers, History, Account or Admin.

## Contract decisions

- Only explicit interface choices are stored under `localStorage['grocery.ui_language']`. Browser detection checks supported `cs`/`en` preferences in order and falls back to Czech. An explicit browser choice takes precedence over loaded account settings, then account preference takes precedence over browser detection. Saving an account interface preference is an explicit choice; selecting browser preference clears the local override. Tokens, account revisions, pantry, presets, bindings and requests stay in memory. Nothing is stored in sessionStorage.
- Recipe language is independent: account recipe preference, then `capabilities.defaults.language`, then the API default `en`. Switching interface language never submits or regenerates a recipe. Generated titles, instructions, merchant content and preset names are literal server/user text.
- Settings PATCH and pantry PUT send `expected_revision`. Pantry writes happen only with Save pantry, and recipe completion never deducts stock. `grams:null` means available stock. Decimal commas are converted to decimal points in wire strings; kilogram-to-gram conversion and display formatting do not coerce quantities through floating point.
- Presets use POST collection, PATCH item and DELETE item with revision query. All saved parameters omit `pantry`, `use_first` and `request_id`. Conflicts require explicit reload and preserve local form edits. A stale preset, unsupported model or unavailable profile is rejected before any controls change. History reuse restores recipe parameters but keeps the current pantry and its priorities; a new submission omits the old request identity.
- Retailer IDs are repeated `retailer` parameters for Offers. A nonempty recipe retailer allowlist supplies searchable checkboxes; an empty allowlist permits typed retailer IDs and means unrestricted retailers. Canonical selects/CSV controls remain for compatibility, with clipped controls removed from keyboard and accessibility navigation.
- Seasonings are default/true/false. Oil is a separate pantry ingredient; no new oil API field is assumed. Nutrition defaults are shown as placeholders so blank fields retain policy behavior. Server policy is read-only, including the fixed lactose-free policy; no unsupported dietary restrictions are advertised.
- Capability metadata supplies localized ingredient labels, profile names, languages, defaults, retailer choices and policy. Catalogue warning codes and no-feasible reason codes produce localized main messages. Original warning/reason strings remain under Technical details. Shopping lines retain retailer, source and shopping context provenance.
- `ApiError` preserves `code` and sanitized `fields`. Known error codes have both translations. Validation locations map to accessible inline messages, invalid state and first-field focus; invalid input and raw validation messages are not echoed. Job status and phase are the actual backend values, with no estimated percentage progress.

## Verification

Run `npm test` in `src/frontend`. These offline tests cover dictionary completeness, typed recipe fields, all API error codes, session behavior, exact decimal strings, revision writes, preset safety and stale account responses.

From the repository root, run `.venv/bin/python -m pytest tests/test_website_browser.py tests/test_website_i18n_browser.py tests/test_website_accessibility_browser.py -m browser -q`. Browser tests use local fixture APIs and Chromium. The existing workflow suite explicitly navigates the panels; bilingual tests cover real account writes, conflict recovery, backend 422 protein validation, checkbox focus, recipe/report generation, request reuse, decimal commas, repeated retailer filters and session cleanup. The independently owned accessibility suite covers language, viewport reflow, keyboard navigation and reduced motion.
